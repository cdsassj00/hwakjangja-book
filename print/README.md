# print/ — 인쇄본·전자책 빌드 (위키독스와 별개)

위키독스는 `TOC.md`·`pages/`·`assets/`만 읽으므로 이 폴더는 동기화에 영향을 주지 않습니다.

## 만드는 법

```bash
python print/build.py --pdf
```

`TOC.md`의 순서와 제목을 그대로 따라 `pages/*.md`를 읽어 크라운판(176×248mm) 책 한 권을 만듭니다.
**새 장을 쓰고 `TOC.md`에 등록하면 자동으로 포함**되므로 빌드 스크립트를 손댈 일은 없습니다.

| 명령 | 결과 |
|---|---|
| `python print/build.py` | `확장자의재발견-크라운판.html` (자체완결 HTML) |
| `python print/build.py --pdf` | 위 HTML + `확장자의재발견-크라운판.pdf` |
| `python print/build.py --only 03` | 3장만 가벼운 미리보기 (집필 중 확인용) |

HTML은 폰트(Pretendard)와 조판 엔진(Paged.js)을 안에 담고 있어 인터넷 없이 열리며, 그대로 전자책 겸 미리보기로 쓸 수 있습니다. 브라우저로 열고 `Ctrl+P`로 직접 PDF를 저장해도 됩니다.

## 알아 둘 점

- **PDF는 조판이 끝나기를 기다렸다가 뽑습니다.** 헤드리스 브라우저로 그냥 인쇄하면 Paged.js가 쪽을 나누기 전에 인쇄돼 앞 몇 쪽만 나옵니다. `build.py`가 쪽 수가 더 늘지 않을 때까지 기다린 뒤 저장합니다.
- **생성된 HTML·PDF는 저장소에 넣지 않습니다**(`.gitignore`). 장이 늘 때마다 10MB 넘는 파일이 커밋되면 저장소가 감당하지 못합니다. 필요할 때 위 명령 한 줄로 다시 만드시면 됩니다.
- `assets/`의 `Pretendard.woff2`와 `paged.polyfill.js`는 빌드에 쓰이는 원본이라 저장소에 함께 둡니다.

## 재단선이 필요할 때

인쇄소 납품용(3mm 블리드 + 재단선)이 필요하면 생성된 PDF를 인쇄소 사양에 맞춰 한 번 더 처리해야 합니다. 원고가 더 쌓인 뒤 실제 납품 시점에 인쇄소 사양을 받아 처리하는 편이 낫습니다.
